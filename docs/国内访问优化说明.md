# 国内裸连"有时候连不上"——不花钱能做到什么，做不到什么

## 一、先把病因说清楚

你的站是 Cloudflare Pages（`nadutong-forum.pages.dev`）。

- pages.dev 的节点**全在境外**（美国/欧洲/亚太部分区域），国内没有节点。
- 实测（青岛家宽直连）：`index.html` TTFB 656ms、`app.js` TTFB 721ms、`main.css` TTFB 654ms。
  这不是带宽慢，是**一个来回就要 650~720ms**。
- 原来首页要发起 **42 个请求**，并且所有响应头都是
  `Cache-Control: public, max-age=0, must-revalidate`，
  意味着**每一次打开、每一个文件都要重新走一遍这个 650ms 的来回**。
  40 次串行/并发混杂的校验 → 首屏就能拖到十几秒，线路一抖就直接超时打不开。

所以"有时候连不上"的大头不是"没有国内节点"，而是**请求太多 + 一次都不缓存**。
这两件事这次已经按住（见 `v100-优化与修复记录.md`）：请求 42 → 5，`/assets/*` 缓存一年。

## 二、不花钱，这 5 件事已经做了

| 手段 | 效果 |
|---|---|
| 40 个资源合并成 3 个 + brotli | 首屏要过的"来回"从 40 次降到 3 次 |
| `/assets/*` 一年 `immutable` | **第二次以后的访问：资源请求基本为 0**，不再回源校验 |
| Service Worker 预热首屏 8 个文件 | 装好后即使那一刻线路抖，页面也能从本地秒开 |
| `index.html` 网络优先 + 3.5s 超时回退缓存 | 线路抖动/断网时不白屏，能进站 |
| 接口 20s 超时 + 只读 GET 重试一次 + 本地兜底 | 弱网下不再"一直转圈到死"，也不会重复发帖 |

一句话：**第一次打开还是那个 650ms 的来回，但从此以后打开是本地秒开**。
这是不花钱能拿到的最大一块收益。

## 三、不花钱还能做的（要你动手，几分钟）

### 1. 绑自有域名（最有效的一招，前提是你手上已有域名）

`.pages.dev` 这个共享域名在国内被干扰的概率明显高于普通域名。
如果你有（或将来有）一个自己的域名，在 Cloudflare Pages 里
「Custom domains」加上它，再把 DNS 指向 Cloudflare，就能拿到：
- 自己的域名 + 自动 HTTPS；
- 走 `xxx.yourdomain.com` 通常比 `xxx.pages.dev` 稳一截（**前提：这个域名本身没被封**）。

这一步**不花钱**（域名你已经有了；Cloudflare 的 DNS 与 Pages 都免费）。

### 2. 多放一条免费线路（镜像站）

同一份静态代码可以零成本再部署一份到 Netlify / Vercel / GitHub Pages，
任意一条线路抽风时你手动把用户导到另一条。三个都是免费额度内够用。

**但有个坑必须知道**：你的论坛依赖同域的 `/api`（Cloudflare Functions + D1）。
把静态站镜像到别家，那家的域名下**没有 `/api`**，登录、发帖这些会失效。
所以镜像站只能当"看得见"的备份，不能当完整替换。真要做得通，得给 Functions 加 CORS 白名单，
这条我**没做、也没验证**，属于后续可选工程，不建议现在动。

### 3. 让老用户"装"下来（PWA）

站里已经有 `manifest.webmanifest` + Service Worker。在手机上「添加到主屏幕」后：
- 图标进桌面，点开是独立窗口，不再每次走浏览器冷启动；
- 配合上面的缓存，等于本地 App 一样秒开；
- 断网还能打开已缓存的首页。

这是免费的，成本只是引导用户点一下"添加到主屏幕"。

### 4. 域名解析层面的免费加固

- Cloudflare 后台开 **Always Use HTTPS**（免费）。
- 免费 DNS（Cloudflare / 阿里云 DNS 免费版）都可以，别用会插广告的野解析。
- 有 DNSSEC 就开，能减少一部分 DNS 劫持型"打不开"。

## 四、不花钱做不到的（别被"免费加速"广告骗）

1. **国内 CDN / 国内节点**：必须 **ICP 备案**（备案要求主体资质，个人站长 + 同人二次创作站点基本备不下来），
   而且备案后 CDN 流量也是按量收费。**不花钱 + 不备案 = 拿不到国内节点**，这条没有捷径。
2. **"免费加速器/免费 CDN 无限流量"**：这类服务要么限期试用，要么拿你的流量做别的事，
   要么直接跑路。不建议把主站押上去。
3. **Anycast 改变物理距离**：Cloudflare 免费版已经是 Anycast，但国内入口仍会绕境外，
   TTFB 650ms 是物理距离 + 链路决定的，改不了。

## 五、如果你将来愿意花一点点钱（仅供参考，现在不用做）

按性价比排序，最便宜的两条：

1. **一台国内轻量云 + 自己反代**：不能解决备案问题，但若有备案域名，几十块/月的国内轻量足够，
   TTFB 能降到 20~50ms。
2. **对象存储 + CDN 的免费额度**：国内几家都有新用户免费额度，**但同样要备案**。

在没有备案域名之前，上面这些都不用考虑——先把"请求数 + 缓存"吃干，
你已经拿到了这个方案能拿到的 80%。

## 六、怎么自己确认效果

1. 浏览器开 DevTools → Network，勾掉「Disable cache」，刷新：首屏应该只有 **5 个请求**。
2. 关掉「Disable cache」再刷新一次（模拟第二次访问）：资源请求应该变成 **0 或来自 Service Worker**。
3. `curl -I https://nadutong-forum.pages.dev/assets/js/app.bundle.js` 应该看到
   `Cache-Control: public, max-age=31536000, immutable`。
   如果还是 `max-age=0`，说明 `_headers` 没上传成功（它是 Cloudflare Pages 专用文件，必须放**仓库根目录**）。

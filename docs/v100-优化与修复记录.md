# 哪都通论坛 · v100 优化与捉虫记录

> 版本号统一为 `v100`（资源地址里的 `?v=100`）。以后每次改完前端要重新出包时，
> 把 `index.html`、`sw.js`、`docs/build-assets.py` 三处的 `100` 一起 +1，否则老用户会读到旧缓存。

---

## 一、先说结论（这次到底优化了哪几件事）

| 维度 | 优化前 | 优化后 |
|---|---|---|
| 首页静态请求数 | **42 个**（14 个 CSS + 26 个 JS + 页面 + logo） | **5 个**（页面 + 1 个 CSS + 2 个 JS + logo） |
| 首页首屏体积（未压缩） | 1,635,605 B | 1,245,425 B（−24%） |
| 首页首屏体积（gzip） | 541,545 B | 389,316 B（−28%） |
| 首页首屏体积（brotli） | 433,628 B | 309,914 B（−29%） |
| 出生地数据（115,976 B） | 每次打开都下载 | 进入八字页才下载，空闲时预取 |
| 静态资源缓存头 | `max-age=0, must-revalidate`（每次访问逐个回源校验） | `/assets/*` 一年 `immutable` |
| 弱网表现 | 接口失败即整站空白 | 超时兜底 + 只读请求自动重试 + 离线可进站 |
| 加载动效 | 最短 1.8s、最长 2.6s 硬等 | 最短 1.0s、最长 1.8s |

**关键点：原来 40 个文件全是 `Cache-Control: public, max-age=0, must-revalidate`。**
你在国内裸连 pages.dev，每个文件都要先"回源校验"一次（实测单文件 TTFB 650~720ms），
40 次校准就是几十秒的等待；而且每次打开都要重来一遍。
这一条是"国内有时候连不上/特别慢"的主因，不是服务器带宽问题。

## 二、加载速度优化（改了什么）

### 1. 合并 + 压缩：40 个请求 → 3 个文件

| 文件 | 说明 |
|---|---|
| `assets/css/app.bundle.css` | 14 个 CSS 按原 `index.html` 顺序拼接后压成 1 个（299,605 B → br 47,189 B） |
| `assets/js/app.bundle.js` | 24 个 JS 按原顺序拼接后压成 1 个（911,635 B → br 236,141 B） |
| `assets/js/bazi-region.js` | 出生地数据，**不再预载**，按需加载 |

顺序严格照抄旧 `index.html`：CSS 靠后覆盖靠前，JS 按执行顺序注册监听器。
拼接时用 `"\n;\n"` 分隔，避免某个文件结尾漏分号跟下一个文件粘成一条语句。
JS 只做空白/语法压缩、**不做标识符重命名**，因为这些文件之间有跨文件全局变量。

重新出包：`python docs/build-assets.py`（需要 Node，esbuild 自动下载）。

### 2. 缓存策略（`_headers`，Cloudflare Pages 专用）

```
/assets/*            → public, max-age=31536000, immutable
/index.html          → public, max-age=0, must-revalidate
/sw.js               → no-cache
/manifest.webmanifest→ public, max-age=86400
```

`/assets/*` 的文件名都带 `?v=100`，换了版本就是新地址，所以可以放心缓存一年。
`index.html` 保持每次校验，保证新版本立刻生效。`netlify.toml` 里同步加了同样规则（备用部署）。

### 3. Service Worker 升级（`sw.js`）

- 版本号 `v100`；`install` 时主动预热首屏 8 个文件（index / bundle.css / bundle.js / preloader / logo / 两个图标 / manifest），单个失败不影响整体。
- `index.html` 走**网络优先 + 3.5s 超时回退缓存**：有网取最新，线路抖动时用本地那份，至少能进站不白屏。
- `/assets/` 走缓存优先。
- `activate` 时清掉旧版本 `ndt-assets-*` 缓存。

### 4. 首页结构（`index.html`）

- 14 个 `<link rel=stylesheet>` → 1 个；26 个 `<script>` → 1 个。
- 新增 `<link rel="preload" as="script">`，让 bundle 与样式表并行下载。
- 加载动效的关键样式继续内联（首屏即刻可绘制，不等 CSS 往返）。
- `og:image` / `og:url` 改成**绝对地址**（原来写的是相对路径，微信/QQ 抓分享卡片时补不出域名，抓不到图），并补 `canonical`。

### 5. 出生地数据按需加载（`bazi.js`）

- 新增 `REGION_SRC` + `loadRegion(cb)`：进入八字页才注入 `bazi-region.js`，加载完成后自动 `addrInit()` 并刷新提示文案。
- 提示文案改为「出生地加载中… / 正在加载出生地数据，稍等即可选择。」，不再是空白下拉。
- 首页空闲时用 `requestIdleCallback` 预取（4s 超时兜底）；`saveData` 或 2G/慢速 3G 环境下不预取，不抢带宽。

## 三、捉到的 bug（已修）

### Bug 1（严重）：聊天"对方正在输入"时整个会话渲染失败

`app.js` → `renderConversationMessages()`：

```js
const out = arr.map(...).join('');
if (_typingTargets.has(typingKey(target))) out += typingBubbleHtml(target, other);
```

`out` 声明为 `const` 却又 `+=`，只要当前会话里有人触发"正在输入"气泡，就抛
`TypeError: Assignment to constant variable.`，`renderConversationMessages` 整体中断，
表现为消息列表不刷新 / 会话白掉。已改为 `let out`。

### Bug 2（低级但真实）：用户对象重复键

`app.js` 约 4180 行：`{ id, id, name: '未知', avatar: '' }` 同一对象里 `id` 写了两遍。
后一个覆盖前一个，此处恰好值相同所以没炸，但属于隐患。已改为 `{ id, name: '未知', avatar: '' }`。

### 顺带修好的体验问题

- `Cloud.request` 没有任何超时，弱网下一个请求能吊死几十秒，界面一直转圈。
  现在每条请求 20s `AbortController` 超时；**只读 GET** 在 network error / 5xx（含 Cloudflare 520~524）时 700ms 后自动重试一次；**写操作绝不重试**（避免重复发帖）。超时文案「网络超时，请稍后再试」，与原「无法连接云端…」文案并存。
- 加载动效硬拖 1.8s（`preloader-tone.js` 的 `MIN`），改成最短 1.0s、最长 1.8s，动画照旧，不再空等。

## 六、发布注意

1. 上传后第一次访问，浏览器会装新的 `sw.js`，`activate` 时会让旧标签自动重载一次——这是正常的。
2. 以后每次改前端 → 跑 `python docs/build-assets.py` → 三处 `100` 都 +1 → 再上传。
3. **不要**把 `_headers` 当注释删掉：删了缓存头就退回"每次回源校验 40 次"的老状态。
4. Cloudflare Pages 的 `functions/`、`D1` 完全没动，不需要重新配置。
